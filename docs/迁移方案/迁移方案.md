# Vibe AStock 跨机迁移方案（Ubuntu → Ubuntu）

> 适用：把当前这台机器（`192.168.15.131`）上的 Vibe AStock 完整搬到另一台 Ubuntu 机器。
> 前提：**代码已在 GitHub（`https://github.com/ten2net/vibe-astock.git`，分支 `main`），不怕丢**。
> 本方案只处理「代码之外、未提交到 GitHub、但新机器必须带走/必须改」的部分。
> 当前基线提交：`489b69e`（迁移时以目标机实际 `git log -1` 为准）。
> 编写日期：2026-11-12

## 0. 先读这一节：迁移的本质

这个系统的数据分三层，**只有前两层需要搬**：

| 层 | 内容 | 来源 | 要不要搬 |
|---|---|---|---|
| 代码层 | Python 后端、React 前端、Dockerfile、compose、脚本 | GitHub | ❌ 不用，新机 `git clone` |
| 私有配置层 | `.env`、小程序私钥、`.local/api.token`、SSH 私钥、Cloudflare 隧道凭据 | 本机、**未提交** | ✅ **必须搬**（已打包） |
| 用户数据层 | 复盘报告、交易日志、Agent 会话/证据账本、计费库、盯盘缓存、微信 token | `~/.duanxian-agents/`、`~/.vibe-astock-agent/` | ✅ **建议搬**（已打包） |
| 可再生层 | `.venv/`、`node_modules/`、各 `dist/`、`__pycache__`、日志、快照缓存 | 安装/运行生成 | ❌ 不搬，新机重建 |
| 浏览器层 | 自选股、研究记录、界面状态、API 配置 | 浏览器 localStorage | ⚠️ **不会随文件迁移**，见 §6 |

**私有配置层 + 用户数据层已打包为**
`docs/迁移方案/vibe-astock-secrets-YYYYMMDD.zip`（本次为 `vibe-astock-secrets-20261112.zip`，约 924K，471 个文件）。
打包清单、落位表、安全提示见包内 `MANIFEST.md`；重新生成用同目录 `pack_secrets.sh`。

> ⚠️ **安全**：zip 内含真实凭据（Tushare token、东财 Cookie、微信公众号 AppSecret、Bark key、小程序上传私钥、SSH 私钥、Cloudflare TunnelSecret、GitHub Pages token）。只走 `scp` / 加密 U 盘等可信通道，落地后删中转副本，**绝不可提交到任何 Git 仓库、网盘或聊天工具**。

## 3. 还原私有文件（关键步骤）

把 zip 传到新机器（示例用 scp，按实际主机替换）：

```bash
# 在【旧机器】执行
scp "docs/迁移方案/vibe-astock-secrets-20261112.zip" <user>@<新机IP>:/tmp/
```

在【新机器】解压并落位。**注意 zip 内分 `repo/` 与 `home/` 两个根，落位不同**：

```bash
cd /data/wangf/agi_ws/vibe-astock        # 仓库根
unzip -q /tmp/vibe-astock-secrets-20261112.zip -d /tmp/vibe-restore

# 3.1 仓库内文件 → 覆盖到仓库根
cp -a /tmp/vibe-restore/repo/.  ./

# 3.2 HOME 内数据 → 覆盖到 $HOME
cp -a /tmp/vibe-restore/home/.  ~/

# 3.3 修正 SSH 私钥权限（否则 ssh / wechat-proxy 会拒绝使用）
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_rsa ~/.ssh/known_hosts 2>/dev/null || true
chmod 600 ~/.cloudflared/cert.pem 2>/dev/null || true

# 3.4 校验落位
ls -l .env .local/api.token miniprogram/ci/private.*.key
ls -d ~/.vibe-astock-agent ~/.duanxian-agents ~/.cloudflared ~/.ssh

# 3.5 删除中转副本
rm -rf /tmp/vibe-restore /tmp/vibe-astock-secrets-20261112.zip
```

zip 内容一览（详见包内 `MANIFEST.md`）：

| zip 内 | 落到新机 | 作用 |
|---|---|---|
| `repo/.env` | `<REPO>/.env` | 所有真实凭据与 Host 白名单（**最核心**） |
| `repo/miniprogram/ci/private.*.key` | 同路径 | 微信小程序上传私钥 |
| `repo/.local/api.token` | 同路径 | 本地 API 访问 token |
| `repo/.local/setup.json` | 同路径 | setup 指纹（非必需） |
| `home/.vibe-astock-agent/` | `~/.vibe-astock-agent/` | Agent 会话/任务/证据账本、计费库、codex 登录态、盯盘缓存 |
| `home/.duanxian-agents/` | `~/.duanxian-agents/` | 复盘报告、交易日志、原始归档、微信 token、缓存 |
| `home/.cloudflared/` | `~/.cloudflared/` | Cloudflare Tunnel 凭据（cert.pem + 各 tunnel JSON） |
| `home/.ssh/` | `~/.ssh/` | SSH 私钥与 known_hosts（wechat-proxy 固定出口用） |

> 数据目录位置由环境变量控制，见 `CODEBUDDY.md`「数据落盘位置」：
> `ASTOCK_AGENT_HOME`（默认 `~/.vibe-astock-agent/`）、`ASTOCK_DATA_HOME`（默认 `~/.duanxian-agents/`）、`VR_DATA_DIR`。
> 若新机器要改到别的路径，**先设好环境变量再解压**，并把 `home/` 下对应目录放到新路径，别再放 `~`。

## 4. 安装依赖 / 重建可再生层

### 方式 A：本地裸跑（开发/单机自用，最贴近当前机器）

```bash
cd /data/wangf/agi_ws/vibe-astock
sh scripts/setup          # 建 .venv、装 Python 依赖、npm ci、构建前端、装 Hugo

sh scripts/start          # 启动，默认 127.0.0.1:8910，只监听回环
```

- 换端口：`sh scripts/start --port 8911`（同时改 `frontend/vite.config.ts` 代理目标与 `.claude/launch.json`，见 `CODEBUDDY.md`）。
- 验证：`curl http://127.0.0.1:8910/api/astock/health`。
- 跑测试：`.venv/bin/python -m pytest tests backtest/tests research_data/tests -q`。

### 方式 B：Docker 部署（当前仓库 `docker-compose.yml` 的完整编排）

```bash
cd /data/wangf/agi_ws/vibe-astock
# compose 通过 env_file: .env 读取凭据；wechat-proxy 挂载 ~/.ssh/id_rsa 与 known_hosts
docker compose up -d --build
docker compose ps
docker compose logs -f vibe-astock-v2     # 按实际服务名
```

compose 里业务数据落在命名卷，容器重建不丢；`~/.cloudflared/*.json` 与 `cloudflared/config*.yml` 配套提供公网入口。

> 两种方式的取舍：**裸跑**简单、改代码即生效；**Docker** 把 Python/Node/Hugo/代理/微信固定出口/定时发布都编排好了，但有几个硬编码要改（见 §5）。按旧机实际用法选一种即可，不必两套都起。

## 5. 迁移后「必改」项（最容易踩坑）

这些值绑定了旧机器的网络环境，**不改会静默失败**：

1. **`.env` 的 `VIBE_ALLOW_HOSTS`**
   当前是 `192.168.15.131,...` 等旧 IP。`server.py` 的 `_ALLOWED_HOSTS` 只认 `127.0.0.1 / localhost / ::1` 与这里列出的 Host；用新机 IP/域名访问却没写进去 → **所有接口返回 403**。
   把新机 IP、以及公网域名（如 `a.luckybrother.cc`）加进去：
   ```
   VIBE_ALLOW_HOSTS=<新机局域网IP>,a.luckybrother.cc,a2.luckybrother.cc
   ```
   若只在旧机同网段回环访问，可暂时只留 `localhost`。

2. **`.env` 的 `VIBE_HOST`**
   当前 `0.0.0.0`（让 uvicorn 绑非回环）。保留即可；若只想本机访问可删掉/留空回到 `127.0.0.1`。

3. **`docker-compose.yml` 里硬编码的代理 `192.168.200.24:7890`**
   出现在 `BUILD_PROXY`、`http_proxy`/`https_proxy`/`no_proxy`、`wechat-proxy`、`review`、`pages` 等多处（约 12 处）。新环境代理不同就全局替换；没有代理则删掉这些 `environment` 项，并相应清理 `no_proxy` 里的旧 IP。`.env.example` 顶部注释也明确：**代理放 compose，不放 `.env`**（因为 `.env` 会被 `duanxian/fetchers.py` 读进 `os.environ`，测试会误判代码改了 `NO_PROXY`）。

4. **`no_proxy` 里的旧机器 IP** `192.168.15.131`、`192.168.200.24` → 换成新机/新代理网段。

5. **Cloudflare Tunnel（若用公网）**
   - `~/.cloudflared/*.json` 里的 `TunnelID` 与 `cloudflared/config.yml`、`config-v2.yml` 的 `tunnel:` 必须对应；compose 里写死了两个具体 UUID 文件名（`3c5b1ac7-…json` 给 `cloudflared`、`17642bd5-…json` 给 `cloudflared-v2`），文件缺失容器起不来。
   - 域名 `a.luckybrother.cc` / `a2.luckybrother.cc` 的 DNS CNAME 仍指向旧 tunnel：要么沿用旧隧道（凭据已在包里），要么在新机 `cloudflared tunnel create` 重建并 `route dns`，同步改 config 与 compose。
   - `cert.pem` 是 `cloudflared tunnel login` 产物，已随包带走。

6. **数据源网络限制（来自实测，别再排查 UA/Referer）**
   本机访问东财 `push2*.eastmoney.com` 的 `/api/qt/clist/get` 会被**直接掐断连接**（`ConnectionError`，非 403/超时），成交额榜等已走 Tushare 降级。新机器网络环境不同，先跑一次取数验证；若同样受限，沿用现有 Tushare 降级路径即可，不要花时间调 UA/Referer/ut 参数。

7. **`ASTOCK_PAGES_TOKEN` / `WECHAT_APPID` / `WECHAT_SECRET` / `BARK_*`**
   凭据本身随 `.env` 带过来了，但确认新机出口 IP 是否需要加白名单（微信公众号/部分 API 有 IP 白名单）；`wechat-proxy` 固定出口用的 SSH 主机指纹也要在新机 `known_hosts` 里有效。

8. **微信小程序私钥**：`miniprogram/ci/private.*.key` 文件名带 appid，若换了小程序主体需重新生成。

## 6. 浏览器 localStorage（务必单独处理）

`CODEBUDDY.md` 明确：**自选股、研究记录、界面状态、API 配置存在浏览器本地存储**，换浏览器或端口都读不到，更不会随文件迁移。

迁移办法（二选一）：
- 在新机器浏览器打开系统后，手动重新配置这几项（最省事）；
- 或旧机浏览器导出：DevTools → Application → Local Storage → `http://127.0.0.1:8910` → 导出相关 key，在新机同域导入。注意**域名+端口必须一致**，否则 key 不生效。

## 8. 回滚与善后

- **回滚**：代码层 `git checkout <旧commit>` 即可；私有层保留一份 zip 备份，重新解压覆盖即可。旧机器在验收通过前**先不要清空**。
- **zip 不该进 Git**：本目录的 `迁移方案.md` 与 `pack_secrets.sh` 可以提交（不含真实值），但 **`vibe-astock-secrets-*.zip` 绝不能提交**。建议在仓库根 `.gitignore` 追加一行：
  ```
  docs/迁移方案/vibe-astock-secrets-*.zip
  ```
  （或把 zip 放到仓库外保存。）本次若不打算提交本目录，可忽略。
- **换机器后重新打包**：在旧机或新机仓库根执行 `bash "docs/迁移方案/pack_secrets.sh"`，会按当天日期生成新 zip 并打印 sha256，便于校验传输完整性。
