# 基于 Vibe AStock 基础设施的创意游戏清单(讨论稿)

版本:v1 · 2026-11-08 · 状态:待团队讨论,未定稿、未排期

## 0. 这份文档是什么

把「用本项目底座做创意游戏」的脑暴整理成候选清单,供团队评审挑选。
**目前只是创意,不代表任何开发承诺**;每个条目给出玩法、复用的现有设施、大致改造量和合规注意点,讨论后勾选立项。

## 1. 为什么这个底座适合游戏化

| 现有设施 | 对游戏的价值 |
|---|---|
| `calc/` 确定性计算库 | 天然裁判:答案、得分都可复算,无法被 AI 编数 |
| 台账 replay(holdings/交易日志) | 天然记分与结算引擎,持仓/战绩页现成 |
| 六阶段研究 pipeline + validator gate | 天然关卡结构与通关门 |
| schedule 定时任务 + 收件箱 + webhook | 每日任务、推送、排行榜通知 |
| backtest 引擎(对话式、基准对照) | 竞技场关卡结算 |
| 明日验证 09:15 锁定机制 | 天然防作弊(事后不可改) |
| Hugo 博客 + 微信发布链路 | 战报、每日一题的分享出口 |
| watch/fflow 实时轮询 | 盘中实时玩法的数据驱动 |

**共同边界(所有玩法通用)**
- 只用「已发生数据 + 模拟结算」,不做实盘跟单、不做收益承诺、不荐股;
- 台账隐私红线沿用:成交、持仓、金额不进 AI 上下文,游戏上下文同样遵守;
- 排行榜以读数理解、形态判定、规则稳健性计分,不以涨跌收益包装。

## 2. 候选清单

### 轻量(数据换皮,基本不动后端)

**G1 · 复盘每日答(读数理解 quiz)**
每天复盘生成后自动出约 5 道题:哪个板位晋级率最高、炸板率环比怎么变、哪个题材分支延续……答案全部由 calc 确定性计算,答错给原文证据链接。
复用:复盘数据包、calc、schedule、微信/收件箱推送。
工作量:小(出题器 + 答题界面 + 计分台账)。
备注:**推荐首发候选**,能直接提升用户对复盘读数的理解。

**G2 · 情绪天气预报员**
情绪档位(冰点/修复/发酵/亢奋/退潮)变天气系统:玩家盘前对今日「天气」下定性判断,收盘后对照真实读数结算连击 streak。
复用:情绪周期指标、明日验证条件框架、台账记分。
工作量:小。

**G3 · 形态捕手打卡**
「分时资金·横盘后拉升」榜变每日寻宝地:玩家盘中圈出「形态最标准」的票,系统按形态参数(带宽、稳步度、斜率切换)给相似度分,**不按涨跌计分**,纯形态判定竞技。
复用:fflow_pattern 参数、Sparkline、45s 缓存轮询。
工作量:小。**推荐首发候选**,形态榜刚做过口径修正,参数可信。

### 中量(要加游戏状态,引擎现成)

**G4 · 连板天梯 roguelike**
每日连板天梯是一层「塔」:玩家用虚拟点数在各板位布阵,次日按真实晋级/断板结算爬塔;题材树当技能树、情绪退潮当环境伤害。结算走台账 replay,战绩页复用持仓页。
复用:连板天梯、晋级率矩阵、holdings 重放、交易日志界面。
工作量:中。

**G5 · 回测竞技场**
玩家用自然语言写规则 → 对话式 backtest 跑历史 → 统一样本期排行榜;可开「同题周赛」:同区间同资金,比规则稳健,最大回撤当生命值。
复用:backtest 工具目录、约束校验、基准对照图、博客战报。
工作量:中。**最能体现「确定性引擎当裁判」的差异化优势**,建议第二批。

**G6 · 龙虎榜侦探社**
每日一案:给出当日龙虎榜样本、封板时间、题材标签,玩家推理「明日延续还是断板」并写理由;次日真实数据揭案,event_study 统计历史命中率,授「侦探段位」。
复用:龙虎榜端点、昨日梯队核验、明日验证 09:15 锁定(防作弊)。
工作量:中。

**G7 · 多空辩论擂台**
现有 debate 变对抗:同一题材玩家分领正/反方,AI 按证据链完整性、反证覆盖度打分,资料缺口扣分。
复用:多空辩论归档、证据编号核对、数字三级复核。
工作量:中。

### 重量(自成小游戏,底座全复用)

**G8 · 产业链炼金工坊**
产业链下钻变合成玩法:龙头→部件→器件→材料逐层解锁,「供给刚性卡口」是稀有装备,扩产/认证周期是装备属性;knowledge/companies 当图鉴,集齐一条链出「不可替代性」套装。
复用:industry-chain SOP、知识档案、六阶段 pipeline。
工作量:大。

**G9 · 研究跑团(六阶段 = 六章)**
个股研究六阶段做跑团主线:profile 角色建档、financials 财报迷宫、risk 反证 BOSS 战(必须找出反证才能通关),validator gate 当关卡门。可与 G8 合并。
工作量:大。

**G10 · 盘中生态缸(盯盘宠物)**
自选池变生态缸:每票一株植物/宠物,封板、开板、放量映射生长/蔫掉动画,收盘按当日形态结算成长值。纯本机渲染,数据只走 watch 视图;只喂自选与公开读数,不碰持仓。
工作量:大(主要在前端表现)。

**G11 · 时间旅行交易所**
历史行情回放做「回到某天」模拟经营:玩家不知未来,按交易日逐日解锁数据,决策写台账,T+1 与费用规则照真实,期末与沪深 300 对照。
复用:交易日历、日 K 端点、台账 replay、holdings_perf。
工作量:大。

**G12 · 微信盘感日报(轻社交)**
公众号每日复盘末尾加「今日一题」,读者回复答案,企业微信机器人统计正确率发周榜。
复用:blog_publish、digest-push webhook、微信草稿箱链路(2026-11-06 已验证可用;群发需后台人工点)。
工作量:中。

## 3. 初步建议(供讨论参考,非结论)

1. **第一批:G1 + G3**——数据、裁判、推送全现成,各一个小模块可跑,且完全不碰荐股红线;
2. **第二批:G5(回测竞技场)**——差异化最强,天然带传播性(战报);
3. 重量级(G8/G9/G11)等前两批验证用户兴趣后再评估。

## 4. 讨论待定问题

- 目标用户是谁:现有复盘用户的留存工具,还是拉新的独立小游戏?
- 计分是否允许涉及模拟收益,还是严格限定「读数/形态/规则稳健」三类?
- 游戏状态放哪:复用 `.local/` 台账体系,还是独立游戏账?
- 是否需要账号/多人排行,还是坚持单机 + 战报分享?
- 微信侧互动(G12)涉及用户回复收集,隐私与合规怎么界定?
